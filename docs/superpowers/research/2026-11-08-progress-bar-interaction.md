# 播放进度条交互修复

日期：2026-11-08。用户指出播放器进度条异常后，继续检查当前本地调试版。

## 复现与原因

1. 模拟器上点击进度条后，整个触摸区域残留白色外框。`GProgressBar` 在点击后请求焦点，绘制焦点框时却没有区分触屏和键盘输入。
2. 按住进度条从约 28 秒拖至曲目后段，已播放轨道随手指变化，下方仍显示 `00:28 / -01:20`。预览位置只存在于进度条内部，时间标签继续读取播放时钟。
3. 松手时立即清空拖动状态，而原生 seek 由控制器延迟调度并异步完成。未完成期间显示旧播放位置，造成回跳。
4. 新增取消操作验证发现：已识别的拖动在收到指针取消时也可能进入结束回调。只依靠拖动取消回调不足以防止误提交。

## 修复

- 焦点框仅在键盘输入模式下显示，保留方向键和无障碍增减操作。
- 进度条向时间标签提供预览位置；封面、歌词页、桌面完整播放器及桌面迷你播放器的已播放/剩余时间同步预览。
- 松手只提交一次 seek，保持目标位置直到异步操作结束。失败则恢复真实时间并允许重试。
- 拖动时显示定位圆点并加粗轨道，拖动起始位置直接匹配手指。
- 收到指针取消时先撤销预览，避免误跳转；切歌会重建时间轴状态，旧预览不带入新歌。
