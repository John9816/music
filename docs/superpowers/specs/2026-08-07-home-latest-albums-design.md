# 首页最新专辑交互与排序设计

## 目标

- 修复首页“最新专辑”卡片无法点击的问题。
- 点击专辑卡片后打开该专辑的歌曲详情页。
- 将“最新专辑”区块移动到“每日推荐”区块之前。
- 保持首页现有视觉风格、音源选择和歌曲播放行为不变。

## 根因

`DiscoverView` 当前只向 `_AlbumCard` 传入专辑数据。卡片没有点击回调、手势组件或导航逻辑，因此点击必然无响应。该遗漏从首页专辑区块首次引入时就存在，不是当前样式改动造成。

## 页面顺序

首页内容按以下顺序展示：

1. 页面标题与问候语。
2. 今日主推。
3. 最新专辑标题和横向专辑列表。
4. 每日推荐标题和歌曲列表。

本次只移动“最新专辑”的标题和横向列表，不改变两个区块内部的样式或数据数量。

## 专辑交互

整张专辑卡片作为点击区域，并使用项目现有的 `GPressScale` 提供按压反馈。点击后通过当前首页导航栈打开 `PlaylistDetailView`。

首页读取当前 `SettingsController.source`，将专辑的 ID、名称、封面和音源转换为详情页使用的 `Playlist` 展示模型。详情页的自定义 loader 调用 `MusicApi.getAlbumDetail(album.id.toString(), source: source)` 获取专辑歌曲。

这个流程复用搜索页已有的专辑导航模式，避免新增一套详情页或重复加载、播放和错误处理逻辑。

## 数据与错误处理

- 专辑列表继续由 `MusicApi.getNewestAlbums` 加载。
- 专辑详情使用用户点击时的当前音源，避免跨音源请求错误。
- 详情加载状态、失败提示和重试继续由 `PlaylistDetailView` 负责。
- 点击卡片只触发导航，不在首页预加载专辑歌曲，也不自动开始播放。

## 实现范围

主要修改 `lib/features/discover/discover_view.dart`：

- 调整两个首页区块的 sliver 顺序。
- 增加打开专辑详情的导航方法。
- 为 `_AlbumCard` 增加必需的 `onTap` 回调和按压反馈。
- 引入现有的 `Playlist` 与 `PlaylistDetailView`。

测试修改放在现有 Flutter widget 测试体系中。不会新建专辑详情页面，也不会调整 API、模型或播放控制器。

## 测试方案

- Widget 测试断言“最新专辑”的垂直位置在“每日推荐”之前。
- Widget 测试点击专辑卡片后断言进入 `PlaylistDetailView`，并验证详情页收到对应专辑信息。
- 测试使用可注入的 `MusicApi` 返回确定的首页和专辑详情数据，避免依赖网络。
- 运行相关 widget 测试、格式检查和 Flutter 静态分析。

## 验收标准

- 首页“最新专辑”显示在“每日推荐”之前。
- 任一最新专辑卡片都可点击，并有现有样式一致的按压反馈。
- 点击后进入对应专辑的歌曲详情页，不直接播放歌曲。
- 专辑详情使用当前音源加载，加载失败时仍可在详情页重试。
- 每日推荐歌曲点击播放和今日主推行为不受影响。
