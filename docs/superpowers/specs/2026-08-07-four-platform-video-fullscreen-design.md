# DuckMusic 四端视频全屏设计

## 目标

- Android、iOS、macOS、Windows 的电视直播与影视播放都提供播放器级全屏。
- 移动端全屏锁定横屏并进入沉浸模式；退出后恢复应用允许的方向和系统栏。
- 桌面端进入原生窗口全屏；`Esc`、系统返回或退出按钮先退出播放器全屏。
- 直播全屏不显示进度、快进或拖动能力；影视全屏保留进度与跳转。

## 方案

统一使用项目现有的 `media_kit` 与 `media_kit_video`。其公开全屏流程已经实现移动端方向与系统栏切换，以及 macOS、Windows 原生窗口全屏，避免维护第二套平台 MethodChannel。

影视播放器从 `video_player` 迁移到 `media_kit`，复用自适应点播控件、全屏路由和原生窗口切换。现有续播、定时保存进度、播放/暂停和投屏连接后暂停本地播放的行为保持不变。

直播播放器继续使用当前 MPV 会话和串行打开队列。为 `Video` 增加专用直播控件：普通模式提供全屏入口；全屏模式提供退出、静音、播放/暂停和线路入口，但不创建任何时间轴或 seek 手势。桌面双击画面切换全屏。

## 生命周期

- 全屏只改变视频展示层，不创建第二个 Player，也不重新打开媒体地址。
- 退出页面前先退出全屏，再沿用现有的错误订阅取消、打开队列排空和播放器停止顺序。
- 影视继续每五秒保存播放位置，并在暂停、切到后台、退出全屏和销毁时保存。
- 直播线路切换继续经过 `LiveOpenQueue`，全屏状态不改变故障转移逻辑。

## 平台行为

- Android/iOS：全屏横屏、隐藏系统栏；系统返回先退出全屏。
- macOS/Windows：原生窗口全屏；`Esc` 和全屏退出按钮恢复原窗口。
- 非全屏布局保持当前桌面最大宽度与移动端安全区规则。

## 测试

- Widget 测试验证直播播放器显示全屏入口，触发时调用媒体会话全屏操作。
- Widget 测试验证直播控件没有进度条或 seek 控件。
- 影视会话测试覆盖打开、续播位置、暂停和进度读取。
- 四端共用逻辑通过全量 Flutter 测试与静态分析。
- 构建 Android Debug、iOS 无签名、macOS Debug、Windows Debug；无法在当前 macOS 主机执行的 Windows 构建必须明确报告。
- macOS 实机验证进入全屏、`Esc` 退出、返回列表和应用退出无新增崩溃报告。

## 非目标

- 本阶段不实现 DLNA/UPnP 设备发现；它在四端全屏稳定后继续。
- 不增加直播回看、时移、快进或转码。
- 不改变直播源、影视源或 HTTPS 中继策略。
