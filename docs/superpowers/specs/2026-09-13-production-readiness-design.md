# DuckMusic 多端可用性与 macOS 分发修复

日期：2026-09-13。基线：`3c61cf5`，`1.1.46+57`，Flutter 3.44.8 / Dart 3.12.2；现有 278 项测试通过。

## 目标与边界

修复 macOS 安装后无法打开的问题，并使现有音乐核心流程在手机、横屏、平板和桌面窗口中可用、可理解、可恢复。用户已授权修复及 UI/UX 实现；本轮在当前干净的 `flutter-migration` 工作区完成可审查改动。发布、上传安装包、修改远程设置和提交应用商店另行处理。

使用现有 Flutter、Provider、主题组件和后端协议。保持 Android 应用 ID、历史生产签名、账户和音乐数据兼容。没有新增依赖或后端接口的需求。正式发布前才递增版本，不能重用已发布标签。

## 视觉与信息结构

沿用项目已确定的品牌色和中性表面：品牌绿 `#2FD365`、提示黄 `#FFD25A`、深色底 `#0D1114`、深色表面 `#1A1F22`、浅色底 `#F2F4F5`、主要文字 `#F5F5F7`。用户选定的强调色继续控制交互焦点。平台系统字体用于正文与操作，粗体标题与等宽数字分别承担分区和播放时间，不为视觉改版引入联网字体。

音乐封面、正在播放状态和真实内容是页面中心。手机底部提供首页、发现、搜索、资料库、我的五个入口；资料库集中收藏、历史、歌单和下载。桌面侧边栏、内容区、可收起的播放面板共享一套尺寸决策，缩窗时保住内容。横屏播放器使用封面和控制双栏，竖屏优先保证播放、进度、收藏和队列操作。

不以换色或增加装饰作为完成标准。保留现有品牌方向，将工作投入到布局、操作密度、状态反馈和辅助功能。

## A. macOS 安装包完整性

现有 CI 构建 ad-hoc 签名的应用后向 `Contents/Resources` 写入 helper，没有重新签名；正式 DMG 也未做 Developer ID 签名、公证与 staple。检查线上 1.1.46 产物以区分封包完整性与系统信任问题。

修复流程：构建与写入 helper → 校验目标架构 → 由内到外签署嵌入代码与应用 → `codesign --verify --deep --strict` → Apple 公证 Accepted → staple 应用 → 创建 DMG → 签名、公证、staple、校验 DMG 与只读挂载产物。正式标签缺少签名/公证配置必须失败；手动诊断构建可以生成明确标记的开发产物，但不得冒充生产安装包。所有凭据仅从 CI secret 读取，日志不得泄露。

本机当前未找到有效签名身份。因此本地可以验证构建、资源 seal、架构、脚本失败行为与启动，不能据此宣称完成 Apple 信任验证。

## B. 自适应主框架

面板实际显示与内容占位必须一致，使用同一个宽度。至少保留 560 px 主内容后才允许固定侧面板，否则使用现有弹层/完整播放页入口。窗口跨越导航断点时保留当前页、子页面和搜索状态；隐藏页不得接收键盘焦点。

收藏/历史页面状态可以缓存，但激活属性不能缓存为首次打开的值。切回历史时重新加载，保留其他页面状态。输入框及可编辑控件获得焦点时，空格、方向键应正常编辑文字；提供桌面搜索快捷键。

## C. 搜索与资料库

搜索布局按实际内容约束决定，缩窗不能改变已完成搜索的语义或丢失结果。下一页为空保留上一个有效页，并禁用无意义的继续翻页；失败重试请求原失败页。已有成功结果在可恢复失败时继续可见。

资料库展示实际歌单与下载数据，区分未登录、加载、空内容、失败和已有内容。失败有可操作的重试；创建/导入后的通知刷新列表；窄屏卡片使用有界或自然高度布局。登录入口可以直接完成下一步操作。

## D. 播放器与通用操作

播放器覆盖 320×700 竖屏和 812×375 横屏，重要控件有明确标签，触摸目标至少 44 px，不能以挤小按钮解决溢出。较低高度允许内容滚动，次级工具合理换行或集中到更多操作。

设置开关支持点击整行、键盘激活以及合并后的开关语义。长设置值与大字可以换行。播放进度支持拖动、键盘左右键、辅助功能增减动作和当前时间描述，纯展示进度不占据键盘焦点。
